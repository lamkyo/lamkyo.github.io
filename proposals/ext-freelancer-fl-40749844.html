Executive Technical Hook — The Three Failures That Kill Ticketing Systems Every sports ticketing system I've audited dies in one of three places. I architect against all three by default: **1. Oversell at the inventory layer.** Two fans tapping the same seat 40 milliseconds apart. If your reservation logic is `SELECT` → check in application code → `UPDATE`, you have a race condition and a refund dispute. Fix: atomic conditional claim at the database level, executed *before* the charge, with an 8-minute hold TTL. ```sql -- The seat is claimed in the DB, or it isn't. No application-level check. UPDATE seat_alloc SET status = 'held', holder = :session_id, expires_at = NOW() + INTERVAL '8 minutes' WHERE id = :seat_id AND status = 'available'; -- 0 rows affected => seat is gone. Return "sold out" and never touch the payment gateway. ``` **2. Static QR codes = free admission.** A screenshot is infinitely copyable. The industry default of "one QR image per ticket" means the first person to the gate wins and everyone else is turned away angry. Fix: **rotating signed tokens** — the wallet renders a fresh code every 30 seconds, signed with a server-held private key, paired with a monotonic counter that the scanner rejects on replay. ```js // Payload rotates every 30s. Scanner verifies signature + rejects any counter <= last seen. const body = Buffer.from(JSON.stringify({ tid, eventId, gate, iat, ttl: 30 })) .toString('base64url'); const sig = crypto.sign(null, Buffer.from(`${body}.${counter}`), privateKey).toString('base64url'); return `${body}.${counter}.${sig}`; // verified offline by the scanner's cached public key ``` **3. The stadium network dies at kickoff.** Cloud-only validation means every gate stalls the moment 40,000 phones join the same cell tower. Fix: the scanner holds a signed, versioned manifest of valid entitlements and validates locally in under 50 ms, queuing scan events for reconciliation on reconnect — with a duplicate-detection ledger so the same token admitted twice raises an immediate gate alert. **The throughput math that drives the design:** a 45,000-seat stadium sees roughly 70% of arrivals in the 75 minutes before kickoff — that's ~31,500 fans through ~40 lanes. **Average ~420 scans/minute, peaking above 1,200.** The validation path must hold p95 under 300 ms at peak. That number determines the caching strategy, not preference. --- ## 2.

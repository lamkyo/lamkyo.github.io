Vulnerability Findings & Proof of Concept

Detailed breakdown of identified security flaws and reproduction steps.

H-01

AaveOracle Fails to Validate Chainlink Price Freshness and Round Completeness

contracts/misc/AaveOracle.sol : getAssetPrice()

Oracle Manipulation Severity: High

Vulnerability Impact

If a Chainlink aggregator stalls, hits its min/max price bounds, or encounters an incomplete round, latestAnswer() silently returns the stale price or erroneous boundary value without reverting. This causes the Aave protocol to compute erroneous health factors during liquidations or allow under-collateralized borrowing based on outdated valuations.

Root Cause Location

int256 price = source.latestAnswer();
if (price > 0) {
  return uint256(price);
} else {
  return _fallbackOracle.getAssetPrice(asset);
}

Proof of Concept (Foundry / Forge)

// Conceptual Foundry test demonstrating stale price exploitation
contract MockStaleAggregator {
  function latestAnswer() external view returns (int256) {
    return 1000e8; // Stale price frozen indefinitely
  }
}
// Even if timestamps are hours old, getAssetPrice accepts 1000e8 blindly.
Remediation: Migrate to latestRoundData() with timestamp & answeredInRound checks.
M-01

Unbounded Loop in ReservesSetupHelper::configureReserves Causes Gas Exhaustion

contracts/misc/ReservesSetupHelper.sol : configureReserves()

Denial of Service (DoS) Severity: Medium

Vulnerability Impact

The configureReserves function loops through an unconstrained ConfigureReserveInput[] calldata inputParams array. If the array size exceeds block gas limits during pool upgrades or governance initializations, the transaction reverts, bricking batch setup operations.

Remediation Strategy

// Implement strict batch size bounds or pagination

require(inputParams.length <= MAX_BATCH_SIZE, "Batch too large");

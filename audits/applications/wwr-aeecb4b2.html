### 2.2 API Design

- **Contract-first.** Every endpoint is defined in an **OpenAPI 3.1** spec. The Angular client is generated from it (`openapi-typescript` / `ng-openapi-gen`), eliminating the classic "frontend guessed the field name" class of bugs.
- **Versioning.** URI-based (`/api/v1/...`) for public surfaces; additive-only changes within a version. Breaking changes ship behind a new version with a deprecation window.
- **Resource semantics.** Predictable REST with cursor-based pagination (`?cursor=&limit=`), sparse fieldsets (`?fields=`), and consistent envelope for errors:

```json
{
  "error": {
    "code": "VALIDATION_FAILED",
    "message": "The given data was invalid.",
    "details": [{ "field": "email", "issue": "already_taken" }],
    "correlation_id": "01J8Z9K3Q7..."
  }
}
```

- **Idempotency.** All non-idempotent mutations accept an `Idempotency-Key` header; the server stores the key→response mapping in Redis for 24h to make retries safe (critical for payment and webhook flows).
- **Auth.** Short-lived JWT access tokens (15 min) + rotating refresh tokens; server-side revocation list in Redis. RBAC enforced at the policy layer, never in the controller alone.

### 2.3 Data Modeling

- **PostgreSQL as the system of record.** Normalized core tables, with deliberate denormalization only where read patterns justify it.
- **Migrations are code.** Every schema change is a versioned, reversible migration; destructive changes follow the **expand → migrate → contract** pattern so deploys never require downtime.
- **Multi-tenancy.** `tenant_id` on every tenant-scoped table, enforced by a global query scope (Laravel) or a repository guard (NestJS), plus **row-level security** in Postgres as defense-in-depth.
- **Auditability.** Append-only `audit_log` table capturing actor, action, entity, before/after diff, and correlation ID — non-negotiable for B2B SaaS.

### 2.4 Concurrency Control

- **Optimistic locking** via a `version` column on mutable aggregates; conflicting writes return `409 Conflict` with the current state so the SPA can reconcile.
- **Pessimistic locks** (`SELECT ... FOR UPDATE`) reserved for short, high-contention critical sections (e.g., inventory decrement, wallet debit).
- **Distributed locks** (Redis `SET NX PX` with fencing tokens) for cross-process coordination — never as a substitute for database constraints.
- **Queue-based serialization** for inherently ordered work (per-tenant jobs routed to a consistent partition).

### 2.5 Caching Strategy

| Layer | Mechanism | Invalidation |
|---|---|---|
| Browser/CDN | `Cache-Control`, ETag, immutable hashed assets | Content-hash filenames |
| API response | Redis, keyed by tenant+route+params | Tag-based purge on write |
| Query | Materialized views for heavy aggregates | Scheduled + event-driven refresh |
| In-app (Angular) | Signal-based memoization, `shareReplay` | Explicit invalidation on mutation |

**Rule:** cache is a performance optimization, never a correctness dependency. Every cached path has a tested cold-cache fallback.

### 2.6 Scalability Guarantees

- **Stateless app tier** → horizontal scaling behind a load balancer; sessions live in Redis, never in process memory.
- **Read replicas** for reporting/analytics queries; the primary handles writes only.
- **Backpressure** via bounded queues and `429` + `Retry-After` on overload — the system degrades gracefully instead of collapsing.
- **Load-shedding** for non-critical endpoints under saturation, preserving the critical path.

### 2.7 Production Readiness

**CI/CD (GitHub Actions reference):**

```
lint → typecheck → unit tests → build → integration tests (ephemeral DB)
     → container image (SBOM + signed) → deploy to staging → smoke tests
     → manual/auto gate → blue-green deploy to production → post-deploy checks
```

- **Zero-downtime deploys:** blue-green (or rolling with readiness gates). Migrations run as a separate, backward-compatible step *before* the new code is live.
- **Observability:** OpenTelemetry traces propagated from Angular (`traceparent` header) through the API into the database, exported to Tempo/Jaeger. Prometheus metrics for RED (Rate, Errors, Duration) and USE (Utilization, Saturation, Errors). Structured JSON logs with correlation IDs, shipped to Loki/ELK.
- **Alerting:** SLO-based (e.g., 99.9% availability, p95 latency < 300ms). Alerts fire on *symptom* (error budget burn), not on every noisy cause.
- **Load testing:** k6 scripts in CI against staging, with pass/fail thresholds on p95 latency and error rate. Chaos drills (kill a replica, drop a dependency) before major launches.
- **Security:** dependency scanning (Dependabot/Trivy), SAST in CI, secrets in a managed vault, least-privilege IAM, and OWASP Top 10 checklist per release.

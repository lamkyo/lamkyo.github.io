## 2. Deep Technical Solution Blueprint

### 2.1 Problem framing

Assume the highest-leverage surface is an **Agent Run Console**: an agent observes a failing pipeline, proposes a remediation (patch + rationale + evidence), and a human approves, rejects, or defers. Requirements:

- **R1 — Provenance.** Every agent claim must be traceable to an artifact: commit SHA, job ID, log slice, test result, trace ID.
- **R2 — Human decision safety.** An approval must be idempotent, single-writer, and bound to the *exact* proposal reviewed (digest), never to a mutated one.
- **R3 — Real-time coherence.** Clients see a monotonic, gap-free, resumable event stream across reconnects, tabs, and mobile networks.
- **R4 — Multi-tenancy.** Tenant isolation at the data layer, not just the query layer.
- **R5 — Operability.** The service must explain itself: per-tenant RED metrics, span-linked logs, and a laggable-but-correct streaming path.

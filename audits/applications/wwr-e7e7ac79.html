## 2. Deep Technical Solution Blueprint

### 2.1 Architectural Thesis

Treat **Privacy Incident Management as a first-class platform service** — a *Privacy Incident Orchestration System (PIOS)* — rather than a set of manual workflows. The system must:

1. **Ingest** signals from heterogeneous sources (CSIRT alerts, DSR anomalies, product telemetry, employee reports).
2. **Triage & classify** severity and regulatory exposure deterministically and reproducibly.
3. **Orchestrate** cross-functional response with clear ownership, SLAs, and audit trails.
4. **Automate** notification workflows, evidence collection, and retrospective tracking.
5. **Measure** program health via incident metrics, remediation status, and trend analytics.

### 2.3 Data Modeling (Postgres — canonical store)

```sql
-- Core incident record
CREATE TABLE privacy_incidents (
    id                UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    external_ref      TEXT UNIQUE,              -- CSIRT / source ticket id
    title             TEXT NOT NULL,
    status            TEXT NOT NULL CHECK (status IN
                        ('triage','investigating','contained','notifying','closed')),
    severity          SMALLINT NOT NULL CHECK (severity BETWEEN 1 AND 5),
    data_categories   TEXT[] NOT NULL,          -- e.g. {PII,financial,biometric}
    jurisdictions     TEXT[] NOT NULL,          -- e.g. {EU,CA,US-CA}
    estimated_subjects INTEGER,
    detected_at       TIMESTAMPTZ NOT NULL,
    triaged_at        TIMESTAMPTZ,
    contained_at      TIMESTAMPTZ,
    closed_at         TIMESTAMPTZ,
    dri               TEXT,                     -- accountable owner
    created_at        TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at        TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- Regulatory notification obligations (clock tracking)
CREATE TABLE notification_obligations (
    id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    incident_id   UUID NOT NULL REFERENCES privacy_incidents(id) ON DELETE CASCADE,
    regime        TEXT NOT NULL,                -- GDPR, CCPA, PIPEDA, ePrivacy
    authority     TEXT,
    deadline_at   TIMESTAMPTZ NOT NULL,         -- computed from detected_at + regime SLA
    notified_at   TIMESTAMPTZ,
    status        TEXT NOT NULL DEFAULT 'pending'
                    CHECK (status IN ('pending','notified','waived','overdue'))
);

-- Immutable audit ledger (append-only)
CREATE TABLE incident_events (
    id            BIGSERIAL PRIMARY KEY,
    incident_id   UUID NOT NULL REFERENCES privacy_incidents(id),
    actor         TEXT NOT NULL,
    action        TEXT NOT NULL,
    payload       JSONB NOT NULL,
    occurred_at   TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_events_incident ON incident_events(incident_id, occurred_at);
```

**Design notes:**
- `notification_obligations` decouples **regulatory clocks** from incident state — a single incident can trigger multiple parallel obligations across jurisdictions.
- `incident_events` is append-only (no UPDATE/DELETE grants) to guarantee a tamper-evident audit trail for regulators and internal review.
- Array columns (`data_categories`, `jurisdictions`) support fast GIN-indexed filtering for trend analytics.

### 2.4 API Design (REST, versioned)

```
POST   /v1/incidents                 # idempotent intake (Idempotency-Key header)
GET    /v1/incidents/{id}            # fetch with obligations + recent events
PATCH  /v1/incidents/{id}            # state transition (guarded by state machine)
POST   /v1/incidents/{id}/events     # append audit event
GET    /v1/incidents/{id}/obligations
POST   /v1/obligations/{id}/notify   # record notification + evidence
GET    /v1/metrics/health            # program health (MTTA, MTTR, SLA breaches)
```

### 2.5 Concurrency Control & Correctness

- **Optimistic concurrency** via `updated_at` / version column on `privacy_incidents`; PATCH requires `If-Match` to prevent lost updates during multi-responder triage.
- **State machine guards** enforce legal transitions (e.g., cannot move to `notifying` before `contained`), preventing inconsistent incident states under concurrent edits.
- **Idempotent intake** keyed on `Idempotency-Key` + `external_ref` to dedupe duplicate alerts from CSIRT and product telemetry.
- **Advisory locks** (`pg_advisory_xact_lock`) around obligation-clock computation to avoid double-notification races.

### 2.6 Caching & Scalability

- **Redis** for hot reads: active incident dashboards, on-call roster, SLA countdowns (TTL-bounded, invalidated on state transition).
- **Read replicas** for analytics queries so Looker/Snowflake extraction never contends with live triage writes.
- **Partitioning** `incident_events` by month for unbounded audit growth.
- **Horizontal scale**: stateless API pods behind a load balancer; workflow workers scale independently via queue depth.

            ]
        )

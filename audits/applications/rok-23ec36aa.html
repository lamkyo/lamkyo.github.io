### 2.2 Core Components  

| Component | Tech Stack | Rationale |
|-----------|------------|-----------|
| **Ingestion** | **Kafka** (or **Pulsar**) + **Kafka Connect** with CDC connectors for relational sources, **S3 source** connector for flat files. | Guarantees **ordered, durable, replayable** streams; native integration with cloud providers. |
| **Stream Processing** | **Apache Flink** (Java/Scala) or **Apache Beam** (Python) running on **Kubernetes** (Flink Operator). | Real‑time **validation, enrichment, and transformation** (e.g., CDISC‑to‑FHIR mapping) with exactly‑once semantics. |
| **Data Lake** | **Amazon S3** (or **Azure Blob**) with **Parquet** + **Iceberg** table format. | Columnar storage for analytics, **time‑travel**, and **schema evolution**. |
| **Metadata & Catalog** | **PostgreSQL** (RDS) + **AWS Glue Data Catalog**. | Central source of truth for dataset versions, lineage, and access policies. |
| **Audit & Compliance** | **Cassandra** (wide‑column) for immutable event logs + **OpenSearch** for searchable audit trails. | Scalable write‑heavy audit logs; searchable for regulator queries. |
| **API Layer** | **Envoy** as sidecar + **Kong** or **Traefik** for API gateway; **OPA** for policy enforcement; **GraphQL** (Apollo) + **REST** (FastAPI). | Provides **fine‑grained RBAC**, **rate limiting**, and **observability hooks**. |
| **Self‑Service UI** | **React** + **Next.js** (SSR) + **TailwindCSS**; **JupyterHub** for data scientists. | Fast, responsive UI with **role‑based dashboards**. |
| **CI/CD** | **GitHub Actions** + **ArgoCD** (GitOps) for Kubernetes manifests; **Helm** charts. | Zero‑downtime deployments, automated rollbacks, and **declarative infra**. |
| **Observability** | **Prometheus** + **Grafana** for metrics; **OpenTelemetry** (OTel) for traces; ** Loki** for logs. | End‑to‑end visibility, SLA monitoring, and rapid incident response. |
| **Security** | **Vault** for secrets; **KMS** for data‑at‑rest encryption; **TLS‑mutual auth**; **SOC‑2** and **HIPAA** compliance pipelines. | Guarantees **data privacy** and **regulatory readiness**. |
| **Testing & Load** | **k6** for load testing; **pytest** + **Testcontainers** for unit/integration; **Chaos Mesh** for resilience testing. | Validates **scalability** and **fault tolerance** before production. |

### 2.3 Concurrency & Consistency  

* **Exactly‑once processing** via Kafka transactional APIs + Flink checkpointing.  
* **Optimistic concurrency control** on metadata (PostgreSQL `SELECT … FOR UPDATE SKIP LOCKED`).  
* **Versioned datasets** using Iceberg snapshots – readers always see a consistent snapshot while writers create new versions.  

### 2.4 Caching & Performance  

| Layer | Cache | TTL / Invalidation | Why |
|-------|-------|-------------------|-----|
| API Gateway | **Redis** (cluster) | 5 min for static catalog, 30 s for query results | Reduces latency for frequent metadata lookups. |
| Data Lake | **Amazon S3 Select** + **Pre‑cached Parquet footers** | N/A (object‑level) | Enables predicate push‑down, minimizing data scanned. |
| UI | **Service Worker** + **IndexedDB** | Session‑based | Offline capability for field staff. |

### 2.5 Production‑Readiness Checklist  

- **CI/CD**: Lint → Unit → Integration → Security (Snyk) → Deploy (ArgoCD).  
- **Observability**: Service‑level objectives (SLOs) – 99.9 % API availability, 200 ms 95th‑percentile latency.  
- **Disaster Recovery**: Multi‑AZ RDS, cross‑region S3 replication, Kafka MirrorMaker.  
- **Zero‑Downtime Deploy**: Blue‑Green with **Istio** traffic split, health‑checks, and canary analysis (Flagger).  
- **Compliance**: Automated HIPAA audit scripts, data‑masking policies enforced by OPA.

## 2. Deep Technical Solution Blueprint

### 2.1 Architectural Proposal: The "Enablement Operations Cloud"

I propose a **three-plane architecture** that mirrors PagerDuty's own Operations Cloud philosophy — separating *signal ingestion*, *intelligence*, and *delivery*.

```
┌──────────────────────────────────────────────────────────────────────┐
│                     ENABLEMENT OPERATIONS CLOUD                        │
│                                                                        │
│  ┌────────────────┐   ┌────────────────┐   ┌────────────────────┐    │
│  │  SIGNAL PLANE  │   │ INTELLIGENCE   │   │   DELIVERY PLANE   │    │
│  │  (Ingestion)   │──▶│    PLANE       │──▶│  (Personalization) │    │
│  └────────────────┘   └────────────────┘   └────────────────────┘    │
│         ▲                     │                       │               │
│         │                     ▼                       ▼               │
│  ┌──────────────────────────────────────────────────────────────┐    │
│  │              UNIFIED ENABLEMENT DATA MODEL (UEDM)             │    │
│  │   Rep · Content · Certification · Deal · Region · Product     │    │
│  └──────────────────────────────────────────────────────────────┘    │
└──────────────────────────────────────────────────────────────────────┘
        ▲              ▲              ▲              ▲
        │              │              │              │
   Salesforce      Clari         Highspot       MindTickle
   Salesloft       LMS           Slack          Workday (HRIS)
```

#### Signal Plane — Ingestion & Normalization
- **Event bus:** Kafka (or AWS EventBridge for managed simplicity) as the backbone. Every source system emits normalized `EnablementEvent` records.
- **Connectors:** Idempotent, rate-limit-aware adapters per source (Salesforce Streaming API, Highspot webhooks, MindTickle SCIM, Clari REST).
- **Schema registry:** Avro/Protobuf contracts so downstream consumers never break when a source changes.

#### Intelligence Plane — Scoring & Attribution
- **Readiness Score Service:** A streaming Flink/Spark job that computes per-rep readiness from certification state, content engagement, and deal outcomes.
- **Attribution Engine:** Joins enablement events to opportunity outcomes (via Salesforce OpportunityHistory) to produce causal-lite attribution — "reps who completed Battle Card X closed 23% faster."
- **Feature store:** Feast or a lightweight Postgres+Redis store so both batch (BI) and online (in-app nudges) consumers read the same features.

#### Delivery Plane — Personalization & Content
- **Content Graph:** A graph model (Neo4j or Postgres with recursive CTEs) linking products → personas → objections → battle cards → certifications. This is what makes "the right content at the right moment" queryable rather than hand-curated.
- **Recommendation API:** gRPC service returning ranked content for a `(rep_id, context)` tuple in <50ms p99.
- **Embedded surfaces:** Slack app, Salesforce Lightning component, and a standalone React portal — all consuming the same API.

### 2.2 Core Components

#### API Design (gRPC + REST gateway)
```protobuf
service EnablementService {
  rpc GetReadiness(ReadinessRequest) returns (ReadinessResponse);
  rpc RecommendContent(RecommendRequest) returns (RecommendResponse);
  rpc RecordEvent(EventRequest) returns (EventAck);
  rpc GetCertificationStatus(CertRequest) returns (CertResponse);
}
```
- **Idempotency:** Every mutating call carries a client-supplied `idempotency_key`; the server dedupes in Redis with a 24h TTL.
- **Versioning:** `v1`, `v2` in the package path; no breaking changes within a major version.
- **Pagination:** Cursor-based (`page_token`), never offset — offsets break under concurrent writes.

#### Data Modeling (Postgres core + Redis cache)
```sql
-- Core entities
CREATE TABLE reps (
  rep_id UUID PRIMARY KEY,
  salesforce_id TEXT UNIQUE NOT NULL,
  region TEXT NOT NULL,
  role TEXT NOT NULL,
  manager_id UUID REFERENCES reps(rep_id),
  created_at TIMESTAMPTZ DEFAULT now()
);

CREATE TABLE content_items (
  content_id UUID PRIMARY KEY,
  source TEXT NOT NULL,          -- 'highspot' | 'mindtickle' | 'internal'
  external_id TEXT NOT NULL,
  title TEXT NOT NULL,
  product_line TEXT,
  persona TEXT,
  UNIQUE (source, external_id)
);

CREATE TABLE enablement_events (
  event_id UUID PRIMARY KEY,
  rep_id UUID NOT NULL REFERENCES reps(rep_id),
  content_id UUID REFERENCES content_items(content_id),
  event_type TEXT NOT NULL,      -- 'view' | 'complete' | 'certify' | 'share'
  occurred_at TIMESTAMPTZ NOT NULL,
  metadata JSONB,
  idempotency_key TEXT UNIQUE
);
CREATE INDEX idx_events_rep_time ON enablement_events (rep_id, occurred_at DESC);
```

#### Concurrency Control
- **Optimistic concurrency** on readiness scores: version column + `WHERE version = $expected` on update. Conflicts retried with exponential backoff.
- **Distributed locks** (Redis Redlock) only for the rare cross-rep aggregation job — never on the hot path.
- **Exactly-once semantics** for event ingestion via Kafka transactional producer + consumer-side dedupe table.

#### Caching Strategy
| Layer | Technology | TTL | Invalidation |
|---|---|---|---|
| Readiness score | Redis | 5 min | Event-driven pub/sub |
| Content recommendations | Redis | 15 min | Content-graph change hook |
| Content metadata | CDN (CloudFront) | 1 hr | Cache-bust on publish |
| Certification state | Postgres materialized view | 1 min refresh | Trigger on cert event |

#### Scalability Guarantees
- **Horizontal:** All services stateless; scale on CPU + queue depth.
- **Target SLOs:** p99 recommendation latency < 50ms; ingestion throughput 10k events/sec sustained; 99.95% availability.
- **Backpressure:** Kafka consumer lag alarms; auto-scale consumers when lag > 10k.

- **Chaos engineering:** Litmus experiments — kill a Kafka broker, partition the network between intelligence and delivery planes, verify graceful degradation.

#### Zero-Downtime Deployment
- **Database migrations:** Expand-contract pattern. Never a destructive migration in the same release as code that depends on it.
- **API compatibility:** Additive-only changes within a major version; deprecation headers with 90-day sunset.
- **Feature flags:** LaunchDarkly (or OpenFeature) for every behavior change; kill switch on every new integration.

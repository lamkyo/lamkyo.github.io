## 2. Deep Technical Solution Blueprint

To scale Upsun’s billing architecture through its next phase of hyper-growth, we must implement a resilient, event-driven Q2C pipeline that decouples high-frequency usage telemetry from transactional financial processing.

```
[ PaaS Infrastructure ] 
         │ (OpenTelemetry / Prometheus Metrics)
         ▼
[ Kafka Ingestion Cluster ] 
         │ (At-Least-Once Delivery)
         ▼
[ DigitalRoute / Custom Mediation Engine ] 
         │ (Aggregation, Deduplication, Windowing)
         ▼
[ Usage Rating Microservice ] ──(Queries)──> [ BillingPlatform / Product Catalog ]
         │ (Async Ledger Commit)
         ▼
[ Immutable Billing Ledger (PostgreSQL / ACID) ]
         ├────────────────────────────────────────┐
         ▼                                        ▼
[ ERP Sync (NetSuite / GL) ]            [ Gateway (Stripe / Invoice Run) ]
  (ASC 606 Revenue Recognition)           (Automated Payment Capture)
```

### Core Architectural Components

1. **Ingestion & Mediation Tier:**
   - **Data Intake:** Raw infrastructure metrics stream from Kubernetes clusters and regional nodes into Apache Kafka topics partitioned by tenant ID to guarantee ordered processing per account.
   - **Mediation & Deduplication:** DigitalRoute or custom Python/Go worker services consume Kafka partitions, applying sliding-window aggregations and idempotency keys to eliminate duplicate usage spikes caused by network retries.

2. **Rating Engine & Catalog Management:**
   - **Dynamic Price Cards:** BillingPlatform is configured with modular product catalogs supporting hybrid pricing models (base subscription + variable metered rates with volume tiering and committed spend minimums).
   - **Idempotent Rating Pipeline:** The rating engine executes batch and real-time rating runs against immutable usage summaries, storing intermediate states in an audit-ready staging table before committing final invoice line items.

3. **Concurrency Control & Consistency:**
   - **Optimistic Concurrency Control (OCC):** Applied to tenant subscription balances and credit drawdowns to prevent race conditions between real-time usage consumption and ad-hoc upgrade/downgrade orders originating from the CRM.
   - **Dead Letter Queues (DLQ):** Automatic routing of sync exceptions, tax calculation timeouts, or pricing schema mismatches into a secure DLQ with automated retry backoff and alerting for Finance/Engineering operations.

4. **Observability & Production Readiness:**
   - **Distributed Tracing:** OpenTelemetry instrumentation across all API boundaries connecting BillingPlatform, Salesforce, and NetSuite.
   - **Metrics & Alerting:** Prometheus monitors lag in Kafka consumer groups, billing run execution durations, invoice generation error rates, and GL synchronization latency.
   - **Zero-Downtime Migration & CI/CD:** Blue-green deployment patterns for rating engine logic updates, with rigorous schema migration testing and backward-compatible API versioning.

"""

Author: Principal Systems Architect
Description: High-throughput usage rating, tier calculation, and atomic 
             ledger commitment engine for hybrid SaaS/PaaS billing models.
"""

from decimal import Decimal, ROUND_HALF_UP
from typing import List, Dict, Any, Optional
import logging
from dataclasses import dataclass
from datetime import datetime

# Configure structured logging
logging.basicConfig(level=logging.INFO, format="%(asctime)s [%(levelname)s] %(name)s: %(message)s")
logger = logging.getLogger("UpsunRatingEngine")

@dataclass
class UsageEvent:
    event_id: str
    account_id: str
    metric_type: str  # e.g., "compute_core_hours", "storage_gb_hours"
    quantity: Decimal
    timestamp: datetime
    idempotency_key: str

@dataclass
class TierRate:
    upper_bound: Optional[Decimal]  # None represents infinity
    unit_price: Decimal

class TieredRatingEngine:
    def __init__(self, catalog_tiers: List[TierRate]):
        # Ensure tiers are sorted by upper bound
        self.catalog_tiers = sorted(
            catalog_tiers, 
            key=lambda t: t.upper_bound if t.upper_bound is not None else Decimal('Infinity')
        )

    def calculate_rated_amount(self, total_usage: Decimal) -> Decimal:
        """
        Calculates cost using stepped/tiered pricing rules.
        """
        remaining_usage = total_usage
        total_cost = Decimal('0.00')
        previous_bound = Decimal('0.00')

        for tier in self.catalog_tiers:
            if remaining_usage <= Decimal('0.00'):
                break

            upper = tier.upper_bound if tier.upper_bound is not None else total_usage + Decimal('1.00')
            tier_capacity = upper - previous_bound

            # Determine usage falling into this tier
            consumed_in_tier = min(remaining_usage, tier_capacity)
            cost_in_tier = (consumed_in_tier * tier.unit_price).quantize(Decimal('0.0001'), rounding=ROUND_HALF_UP)
            
            total_cost += cost_in_tier
            remaining_usage -= consumed_in_tier
            previous_bound = upper

        return total_cost.quantize(Decimal('0.01'), rounding=ROUND_HALF_UP)

class BillingLedgerManager:
    def __init__(self, db_connection_pool: Any):

    def process_account_rating(self, account_id: str, events: List[UsageEvent], committed_credit: Decimal) -> Dict[str, Any]:
        """
        Processes a batch of usage events for an account within a transactional boundary,
        applying commitment drawdowns and ensuring idempotency.
        """
        # Example tier structure: 0-1000 units @ $0.05, 1000+ units @ $0.03
        tiers = [
            TierRate(upper_bound=Decimal('1000.00'), unit_price=Decimal('0.05')),
            TierRate(upper_bound=None, unit_price=Decimal('0.03'))
        ]
        engine = TieredRatingEngine(tiers)

        total_quantity = sum((e.quantity for e in events), Decimal('0.00'))
        raw_cost = engine.calculate_rated_amount(total_quantity)

        # Apply commitment-plus-usage logic (draw down from prepaid commitment)
        billable_amount = max(Decimal('0.00'), raw_cost - committed_credit)
        credit_consumed = min(committed_credit, raw_cost)

        ledger_record = {

            "total_quantity": str(total_quantity),
            "raw_cost": str(raw_cost),
            "committed_credit_applied": str(credit_consumed),

            "processed_at": datetime.utcnow().isoformat(),

            return ledger_record
